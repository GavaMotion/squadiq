# SquadIQ — Android (Google Play) build

This is the Trusted Web Activity (TWA) wrapper that ships SquadIQ to Google Play.
It's a thin native shell around the live PWA at `https://squadiq-coach.vercel.app`
— there is no app-specific Android code to maintain; the whole app is the web app.

Generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap). Committed
here so future updates (and Play Billing work) are reproducible instead of being
re-derived through PWABuilder each time.

> **Why not PWABuilder?** Its Bubblewrap template compiles against the new SDK but
> still emits the *old* `targetSdkVersion`, and its UI exposes no target-SDK control.
> Google Play requires `targetSdkVersion 36` for updates from **2026-08-31**, so we
> build locally where that's a one-line change in `app/build.gradle`.

## What is NOT in the repo

- **`signing.keystore`** — the upload key. Gitignored. The canonical copy (with
  passwords) is the original PWABuilder bundle at
  `C:\Users\Rodrigo\Downloads\SquadIQ - Google Play package.zip`
  (alias `squadiq-key`). Its SHA-256 must match the **first** fingerprint in
  `public/.well-known/assetlinks.json`. Drop it in this folder as `./signing.keystore`
  before building.
- `build/`, `app/build/`, `.gradle/` — generated.

## Prerequisites (one-time)

```bash
npm i -g @bubblewrap/cli      # self-installs JDK 17 + Android SDK into ~/.bubblewrap/
```

**AVG Antivirus MITMs TLS** on this machine ("AVG Web/Mail Shield Root"), which makes
Java/Gradle/sdkmanager downloads fail with *"Failed to download any source lists"*.
Import the AVG root into the Bubblewrap JDK's truststore once:

```bash
# export the root from any https chain, then:
keytool -importcert -trustcacerts -cacerts -storepass changeit -noprompt \
  -alias avg-web-mail-shield -file avg-root.pem
# keytool lives in ~/.bubblewrap/jdk/jdk-17.0.11+9/bin/
```

(Same interception that forces `--use-system-ca` for the Node tooling.)

## Build a new version

1. Bump `versionCode` (and `versionName`) in `twa-manifest.json` **and**
   `app/build.gradle` — keep them in sync. `versionCode` must strictly increase.
2. Put `signing.keystore` in this folder (see above).
3. Build the signed App Bundle. Bubblewrap's `build` wrapper is broken on Windows
   (`'gradlew.bat' is not recognized`), so invoke Gradle directly:

   ```bash
   export JAVA_HOME=~/.bubblewrap/jdk/jdk-17.0.11+9
   export ANDROID_HOME=~/.bubblewrap/android_sdk
   ./gradlew.bat bundleRelease --no-daemon -Dorg.gradle.jvmargs=-Xmx768m
   ```

   (The template's default 1536m heap fails to reserve in this environment; 768m is fine.)

4. Sign the bundle with the upload key:

   ```bash
   ~/.bubblewrap/jdk/jdk-17.0.11+9/bin/jarsigner \
     -digestalg SHA-256 -sigalg SHA256withRSA \
     -keystore signing.keystore app/build/outputs/bundle/release/app-release.aab squadiq-key
   ```

5. Verify before uploading:

   ```bash
   jarsigner -verify -certs app-release.aab   # fingerprint must match assetlinks.json
   ```

   The output AAB's `base/manifest/AndroidManifest.xml` (protobuf, but attribute
   values are plain ASCII you can grep) should show `targetSdkVersion "36"`.

6. Upload at **Play Console → Test and release → Production → Create new release**,
   review, then **Publishing overview → Send changes for review**.

## Regenerating from scratch

If `twa-manifest.json` needs to change materially (icons, host, colours), run
`bubblewrap update --skipVersionUpgrade` (plain `update` prompts for a versionName
interactively), then re-apply `targetSdkVersion 36` in `app/build.gradle`.
